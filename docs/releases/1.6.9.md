# 1.6.9 Windows 宿主交接与设置兼容验收

后续公开包复测发现：解包后再次安装可能因 Windows 相对 junction 指向错误而失败。1.6.9 已改为预发布，请使用 [1.6.10](1.6.10.md)。下面保留当时实际完成的测试，不将其等同于整个安装链均已通过。

环境：Windows 11 专业版 build 26300，签名有效的官方 DSH Desktop 0.2.1-rc.2，Electron 44.7.0。使用隔离应用副本、独立 profile 和 user-data-dir，不复制账户凭证，不更改既有生图服务、网络代理或默认 DSH 数据目录。

## 修复

- #10 / PR #11：应用磁盘补丁后使用有握手、日志、超时和归档校验的等待助手。不定时退出 host，不杀应用，不自动重新启动。退出后保留唯一原归档备份，核对 SHA256 再记录完成。
- 实机额外发现 Electron 的 Windows detached PowerShell 可以退出 0 却不执行脚本。使用短 broker 启动独立助手，分别记录 broker 和助手启动错误。回归验证助手能在 Electron 启动进程结束后继续完成换包。
- #9：现代设置服务保留原生 describe/replace，不暴露 legacy register。升级时仅移除已知旧 shim，保留原生设置事件与用户数据；未知修改停止诊断，旧宿主保留兼容接口。
- 修复备份描述符未关闭导致的 Windows 文件替换失败；备份失败停止写入。安装后验证实际代码版本，修复回滚目录链接令重新升级仍加载旧包的问题。
- 用户须知独立携带弹窗样式；保留用户自行确认。磁盘补丁与当前进程加载状态分别标注。

## 真实机器结果

1. 正式 Desktop 运行时完成安装、备份、回滚到 1.6.8、重新升级到 1.6.9。当前提示词、回滚后新增的提示词内容及 profile 配置保持不变。
2. 对真实宿主执行逐文件备份、完整补丁应用、还原和重应用，失败项为 0；还原后的设置模块与原始字节一致。
3. 从实际桌面 host 的应用接口触发新助手，确认 waiting_for_quit、助手位于桌面会话、host 继续响应。按测试授权关闭隔离副本后，助手完成换包，归档备份 SHA256 一致，没有自动重开。重新打开后接口返回 sealed=false、handoff=complete、插件 1.6.9。
4. 重载后的宿主层、运行时注入注册层和布局层自检均为 ok。隔离 profile 沿用宿主默认权限，因此权限选择这一配置层不标绿；为保持配置不变，没有为了自检改写其权限。自检状态不等于任意模型输出验证。
5. 使用真实 Settings、ConfigEditor 与 Loader 启动独立测试 profile，重复读取设置三次、保存并回读成功，legacy register 不存在。
6. Windows PowerShell 5.1 专项 12 项通过；PowerShell 7 的交接专项 6 项通过。另有真实 Electron 父进程退出后的交接回归。macOS 主测试 100 项通过、4 项 Windows 条件项跳过，界面组件 9 项及真实 Electron ASAR 自检通过。

## 验证边界

此记录覆盖上述安装、更新恢复、宿主补丁交接、原生设置与状态接口。UU 桌面能够显示应用，但自动鼠标输入不稳定，不能据此宣称每个 Windows 页面控件都完成了人工点击验收；没有测试账号登录流程、任意模型的拒绝率或所有第三方插件组合。新旧设置兼容、等待助手异常分支与页面行为另有自动化回归。

默认行为仍不自动重启 DSH。用户明确授权的测试重启属于验收操作，不改变插件默认策略。主机地址、真实路径、配置正文和账户信息不进入发行包或公开证据。
