# 1.6.10 Windows 解包后再次更新验收

1.6.9 的桌面换包与设置接口测试通过后，公开安装入口复测发现另一个阶段的问题：换包之后再次安装，CLI 找不到 app/runtime 下的 pnpm。1.6.9 随即转为预发布，停止作为正式更新推广；不重写已发布 tag。

## 根因与修复

Windows junction 的相对目标按进程工作目录解析，原先的 `..\runtime` 因此可能指向错误位置。改为绝对的同安装 resources/runtime；旧错误链接改名保留，不删除链接目标或目录内容。已有的实际目录和不同的有效运行时链接遇到冲突会停止，不擅自覆盖。

修复同时用于宿主解包和独立安装器。安装器在调用当前实例的解包 CLI 前检查链接；换包前若 pnpm 运行时不可用，助手保留原归档并报错。旧版本已经坏掉的更新器不能自动加载新逻辑，应使用 README 的独立 Windows 安装入口安装 1.6.10。

## 已验证

- Windows 11、真实官方 DSH Desktop 0.2.1-rc.2，独立应用、profile 和 user-data-dir。
- 在真实归档已移走、GUI 已重新加载的状态下，从 1.6.9 安装 1.6.10 候选；旧错误链接被保留，原生 Desktop CLI 的 pnpm 调用成功，提示词及配置 SHA256 不变。
- 在上述解包宿主完成真实快照、回滚到 1.6.8、重新升级到 1.6.10；当前提示词和备份后新增内容均保留。快照即时校验成功，后续旧快照按既有保留策略清理，不为测试修改用户保留设置。
- 16 项 Windows 专项通过，包含真实 Electron 父进程退出交接、缺少运行时拒绝换包、绝对 junction、错误链接保留、安装器当前实例定位，以及原生设置兼容。
- macOS 主测试 103 项通过、5 项 Windows 条件项跳过；面板与 Electron ASAR 回归保留。

1.6.9 的 #9、#10、PR #11 修复继续保留，见对应验收记录。UU 鼠标自动化不稳定，因此不宣称每个 Windows 控件、账户登录或任意模型输出都做过人工操作验证。没有修改用户默认 DSH 数据、代理或生图服务。插件默认仍不自动重启；测试重启仅在用户授权的 Windows 隔离副本中进行。
